# Fauna UI critique

Follow the [UI task procedure](../../../Docs/UI.md#required-review) for the applicable evidence tier and completion rules. Inspect the full frame and changed flow before reading the author's rationale. If only source is available, capture the permitted focused preview or report the missing evidence.

A critique request calls for findings, not production edits unless the user also requests fixes. If captures omit a relevant state or do not identify their source and conditions, limit conclusions to what they show. A screenshot can establish appearance, but a claim about activation, cancellation or focus return needs exercised interaction evidence.

Apply the [copy and layout rule](../../../Docs/UI.md#copy-and-layout): Avoid taglines, avoid helper text, avoid secondary labels - if a screen needs them to make sense, fix the layout instead.

Assess composition, copy, artwork, contrast, fit and interaction against the requested direction and accepted reference scope. Check computed text/icon colors against the rendered fill, including hover and focus overrides. Preserve useful rules, availability reasons, accessible names and minimum hit areas.

Prioritize findings by player impact. For each finding, identify the screen/state, visible evidence, player consequence and smallest useful correction. Do not invent findings to fill a quota; report when the inspected scope has no actionable defects. Separate observed defects from design hypotheses. After correction, inspect fresh captures independently. Only the user's explicit choice establishes artistic approval.
