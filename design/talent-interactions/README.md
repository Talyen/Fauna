# Talent state fine-tuning

Open `/design/talent-interactions/index.html` to try the phone-reviewed talent direction and compare three remaining details: unowned icon strength, hover brightening and purchase flash shape. Each step varies one detail and holds the rest at the stated baseline. Available, owned and locked instances use the same real talent definition for comparison. Poison and Burn contexts use keyword-colored Lucide icons. Labels above controls identify the demonstration state, rather than proposing permanent in-game state labels.

The baseline preserves normal outlined available controls with gold hover, full keyword-colored owned icons on black without checkmarks, 45% opacity for unmet requirements with immediate above/focus tooltips, no hover growth, 150ms ownership color transition and a 250ms purchase flash. The user selected 65% unowned icon strength, 20% hover brightening and a gold-then-fade purchase flash. Settings use `fauna-design-talent-picks-v1`; explicit choices survive reload and can be copied from the combined review. Storage and clipboard failure remain visible.

Activate an available sample to simulate purchase, then Replay purchase to reset it. Owned and locked samples remain inspectable but cannot purchase. Simulation never loads game state, awards talents or saves progression. Flash timers clean up on replacement/unmount; keyboard focus suppresses the flash to preserve one highlighted boundary. Reduced motion disables transitions and flash. Actual shadcn Button, Tooltip, Tabs, RadioGroup and Switch retain their standard behaviors.

[Phone decisions](../PHONE_DECISIONS.md) remain authoritative for approved design intent. Production adoption is recorded in the [shared design system](../../Docs/DESIGN_SYSTEM.md); full rendered journeys, CI, desktop and physical-controller acceptance remain separate.
