# Interactive UI review

Review every Fauna UI element through playable HTML comparisons built from the registered shadcn/ui primitives and the real gameplay compositions. Keep the black, charcoal, ivory and gold foundation. Ordinary buttons have visible boundaries; primary actions use gold fill. These are review constraints, not permission to change every production component immediately.

## Decision process

1. Review one component and one behavior at a time. Compare multiple meaningful options while holding all other appearance, content, dimensions and behavior constant. Separate fill, border, movement, outline, timing, feedback and availability decisions.
2. Explain the options and a recommendation. Make several independent steps available in advance with Next/Previous navigation and saved choices; do not require a chat turn between decisions. Let the player try pointer hover/press, keyboard focus/activation and relevant value/selection changes before choosing. Demonstrate failure and cancellation where applicable. Preserve standard shadcn interaction contracts.
3. Record preferences independently, with undecided states explicit. Assemble chosen behaviors in a separate combined preview only after individual review. Then check interacting states such as selected plus focused, or disabled plus hovered.
4. Review the composition in actual screen contexts before changing production. Record acceptance and verification boundaries. Existing documented rules remain in force until explicitly revised by the review.

Every element gets resting, hover, focus, pressed/dragging, selected/checked, unavailable, busy, error and completion review **where applicable**. Mark irrelevant states as not applicable; do not make passive text or readouts artificially clickable. Include input modality changes, enlarged text, reduced motion and muted operation. Controller simulation and physical hardware acceptance are separate from native keyboard review.

## Context acceptance

After component decisions, test their combined use in main menu, Pause, starters, destinations, battle, targeting, Swap, Victory/replacement, Campfire, results, Collection/paging, talents, Settings, Glossary, Deck/piles, nested inspection and recovery/diagnostics. Use the required viewport and input coverage in [UI rules](../Docs/UI.md#required-review). Test screens reached through their real flows, including cancellation and return focus. Do not infer full-game acceptance from component samples.
