# Script implementation map

[Contributing](../CONTRIBUTING.md) owns command selection and verification policy; [AGENTS.md](../AGENTS.md) owns authorization and invariants.

Implementation folders follow workflows: `agent/`, `assets/`, `balance/`, `checks/`, `ci/`, `dev/`, `performance/` and `release/`. Shared Node infrastructure remains in `lib/`; balance analysis lives beside its commands in `balance/`, and performance metrics and route definitions live in `performance/`. Interaction replay validation remains shared because both performance tooling and CI consume it. Worktree creation, cleanup and integration retain their root entrypoints. Use the existing npm commands from any task checkout; file moves do not change command names or verification policy.

CI orchestration and completeness are owned by [ci.mjs](ci/ci.mjs) and the [workflow](../.github/workflows/ci.yml). The build job assigns exact Playwright test lists by the duration estimates in [browser-durations.json](ci/browser-durations.json); new cases remain included with a default weight. The gate exports refreshed estimates in `browser-review` and checks commit/run identities and matching build hashes across rerun attempts, all discovered browser cases, upstream job results, unit results and the seeded interaction trace. Unit totals must match the recorded passing assertions; the mixed interaction trace must contain valid actions and a checkpoint hash for every completed step. [ci-timings.mjs](ci/ci-timings.mjs) records GitHub job and step timings for a run and optional attempt; see [CI measurements](../Docs/archive/CI_SPEED_PLAN.md#baseline-and-success-measures).

## Bundle allowance

[bundle-budget.mjs](checks/bundle-budget.mjs) owns the current baseline (774,677 uncompressed JavaScript bytes), allowance (800 KiB) and warning threshold (95%). The [measurement history](../Docs/archive/BUNDLE_SIZE_HISTORY.md) retains build identities and the reasons for previous changes. CI measures the exact pushed commit; the recorded baseline establishes size only.

The checker sums all JavaScript files recursively and rejects missing or empty entry bundles. Chunk splits do not create extra allowance. Investigate unexpected growth before raising the ceiling; update the measured baseline and reason together when intentional growth needs a new allowance. This gate measures JavaScript size, not artwork downloads, frame pacing or device performance. Run it against an existing build; build execution follows [the single verification policy](../CONTRIBUTING.md#execution-and-evidence).

Dependency security is owned by [security-audit.mjs](checks/security-audit.mjs) through `npm run security:audit`. The expiring build-tool advisory exception is documented in [CI](../Docs/CI.md). [Periodic performance](../.github/workflows/performance.yml) runs the existing capture/comparison commands, including the optional compiler build. [Signed Windows candidates](../.github/workflows/release-candidate.yml) use `npm run package:installer`; see [release qualification](../Docs/RELEASE.md#candidate-signing-and-qualification).

`npm run check:types` uses [typecheck.mjs](checks/typecheck.mjs) to report every compiler environment in one CI pass. Static CI runs the type, lint, formatting, boundary and unused-code commands independently, retaining failure status while reporting all categories. `npm run check:full` remains their sequential entrypoint.

Production builds run `npm run generate:release-inventory` through [dependency inventory](release/dependency-inventory.mjs) to package dependency and license notices. Its `--package` mode retains final Windows component hashes; see [release provenance](../Docs/RELEASE.md#dependency-inventory-and-provenance).

## Task check implementation

Selection uses the recorded worktree base, including committed and working changes. Unregistered non-main checkouts fall back to their common ancestor with main without requiring a branch prefix. Empty selections explicitly report that no checks ran. `--working-tree` and `--diff` select HEAD explicitly. `--test <suite>` adds a named regression without replacing selection; `--diagnostic <mode>` dispatches the existing bounded launcher. There is no passing-check cache. [Input identities](checks/input-identity.mjs) detect repository changes during verification and bind captures to their renderer, media, fixtures, tooling and runtime. Installed dependencies are not recursively fingerprinted; each gate executes against the current installation. `verify` remains a compatibility alias of `verify:changed`; `npm test` always runs Vitest and `npm run check` always runs full static checks.

The plan prints formatting batches, compiler environments, documentation coverage and required suites with their boundary rationale. Import-related suggestions and unresolved imports appear only with `--related`. Formatting and lint batch at most 50 files, 256,000 source bytes and 8,000 argument bytes; larger single files run alone. Selected source receives architecture/UI contracts across all batches. Deleted sources still select their compiler environment; dependency/configuration changes select all environments.

Changed suites, filename-matched suites and the longest matching prefix in [test-owners.json](checks/test-owners.json) form the required set. Each registry entry explains its boundary rationale; update it when moving an owner or its contract suites. Import discovery is opt-in and only suggests additional suites; timing history never changes the gate. Explicit `--test` suites are recorded in [task intent](lib/task-intent.mjs) and always run at integration without repeating arguments. Intent survives failed checks; `--forget-test` removes obsolete selectors. Plan mode is read-only. Tests run together with one worker, fail-fast and a five-minute deadline; results go to ignored `reports/task-tests.json`. Changed non-documentation files without matching suites fall back to labeled smoke; documentation-only changes need no tests. An empty changed-file selection runs no checks.

The diagnostic launcher accepts `types`, `static`, `build`, `unit [suite files]`, `browser <route>` and `performance <scenario>`. Omitting unit suite paths selects the full unit/DOM set. It validates named files/routes before launching, uses one unit worker, a 2 GiB Node heap and a five-minute deadline, and owns cancellation of its command tree. Browser routes are battle, settings, collection, progression and persistence; performance scenarios are battle, swap and menus. Build first for production browser/performance diagnostics. These limits are enforced by tooling rather than additional approval steps.

## Worktree operations

The [shared command launcher](local.mjs) applies local worker, heap and deadline budgets to ordinary test/static/build/browser/verification commands. Nested recipes share the outer process group and deadline; CI keeps its workflow budgets. It also prepares missing or mismatched dependencies through the existing dependency owner. CSS guards use [PostCSS](https://github.com/postcss/postcss) to inspect declarations and rules without treating comments or quoted content as CSS structure. Primitive provenance lives in the registry.

The command creates `.worktrees/<task-name>` on `task/<task-name>` from committed local main by default. An existing matching checkout is reused without resetting files. Existing branches without that checkout and conflicting directories are preserved and rejected. Dependencies are linked from main only when dependency manifests, install settings and lifecycle scripts match. Run `npm run deps` in the task checkout when dependencies are missing or change: it reuses a matching shared link or detaches only that link and runs `npm ci` locally, using the project-pinned npm without changing the global install. Never run `npm ci` through a shared dependency link. Changing ordinary npm task commands alone does not invalidate dependencies.

Review the task diff and commit task-owned files. From the task checkout, run the single final gate:

```sh
npm run finish
```

Integration holds one repository-wide lock, incorporates the locked main commit in the task checkout, checks the combined result and advances clean main. Separate pre-integration verification is optional. Recorded extra regressions are reused; `--test <suite>` can add more at finish; narrowing the combined changed-file gate is not supported. Dirty checkouts and unfinished Git operations block it. A competing integration waits up to 30 seconds, then preserves task work if still busy; retry later without terminating its owner. The OS file lock releases on exit, including crashes, and a separate owner record supplies PID, checkout, branch and start time. [fs-native-extensions](https://github.com/holepunchto/fs-native-extensions) supplies cross-platform OS locking as a development-only dependency. The first upgrade briefly reserves the previous socket protocol until its bounded waiters expire; a persistent lock file makes older tools refuse new integrations. Legacy directory locks remain protected. Never delete the persistent lock file to unlock integration. Both worktrees are rechecked before main advances. Failed checks preserve committed task work. Successful integration returns `integrated: true`, the commit and the retained worktree path. It never retires the checkout or branch; evidence links and the chat's working directory remain usable. Cleanup is a separate optional operation. Git authorization is defined only in [AGENTS.md](../AGENTS.md#worktrees-and-integration).

Optional repository maintenance, independent of completing an implementation task: audit accumulated local task branches and worktrees from clean main:

```sh
npm run worktree:cleanup
# Remove eligible merged tasks:
npm run worktree:cleanup -- --apply
```

Only local branches under `task/` or `codex/` whose commits are already in main are eligible. The sweep uses the integration lock and preserves dirty, unmerged, locked and unfinished checkouts. It never merges unreviewed work, forces removal, deletes remote branches or terminates preview processes. Preserved tasks are expected and reported without failing the sweep; they do not block another task. Operational failures such as an unavailable lock still fail. Integration performs no cleanup, so retained task checkouts are never swept during routine integration.

Before removal, ignored artifacts (reports, screenshots, logs and other ignored files) are copied to `fauna-worktree-archives/` inside the shared Git directory, with a manifest identifying the original checkout, branch and commit. Dependency installs and links under the checkout's root `node_modules` are disposable and are not archived. Archives remain local and are never automatically deleted; find them with `git rev-parse --git-common-dir`. Tracked and untracked changes always block removal. Close owned preview processes before retiring a checkout; cleanup does not stop processes or establish that another chat has finished. Integration itself retains the checkout.
