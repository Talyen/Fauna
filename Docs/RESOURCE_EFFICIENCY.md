# Disk and memory efficiency

Preserve artwork pixels, audio bytes, command behavior and save ordering. Optimize duplicate storage and resource lifetimes before considering new media formats or smaller artwork. [Contributing](../CONTRIBUTING.md#execution-and-evidence) owns local execution limits; builds, native performance and packaging remain CI-owned.

## Inventory and budgets

Run `npm run resources -- --out reports/resources/inventory.json` to record source identity, unique active media bytes and existing renderer/package sizes without building. `--local` additionally audits registered worktrees, dependency compatibility and archived task storage. Reports distinguish logical file sizes from `du` allocation; APFS shared extents mean allocated totals are not a guaranteed reclamation estimate. Inventory never deletes or installs anything and refuses to overwrite an existing report.

`--evidence` optionally streams SHA-256 checks over same-size bulk files in retired task archives and main's reports. It proposes exact duplicate groups with one retained copy, file sizes and modification identities. It preserves small summaries and bundles marked `.retention-keep`, skips unstable files and performs no deletion. Historical evidence remains outside the automatic expiration policy; a deletion review must recheck both retained and duplicate copies and establish inactivity.

Count unique media URLs, not asset IDs. Use the generated inventory for current totals; the [inventory history](task-evidence/2026-10-24-resource-efficiency.md#inventory-history) retains earlier counts, byte totals and corrections. [Build media validation](../scripts/assets/active-assets.mjs) owns the active-media allowance and per-image ceiling. The October 27 inventory contains 367 unique objects at 264.72 MiB; ten additional approved Boon portraits account for 6.81 MiB of growth from the previous 257.91 MiB inventory. The 268 MiB allowance retains approximately 3.28 MiB of headroom without changing image encoding. The [bundle allowance](../scripts/checks/bundle-budget.mjs) remains separate. CI retains a renderer/package inventory and Linux build maximum-RSS observations under `reports/resources/`. GNU time's maximum RSS is the observed command/child high-water mark, not a sum of every process's simultaneous RAM.

`nominalRgbaBytes` is image dimensions multiplied by four; it is not resident memory, VRAM or a promised optimization saving. Establish game-memory budgets from repeated matching-runtime captures, retaining process identity, conditions and cold/warm status. Never add process working sets into a purported unique-memory total because shared allocations can be counted repeatedly.

## Build and package lifetimes

Local `package:win` stages each development package in `release/.fauna-development/`, records its outcome, and removes sealed, unchanged failed or older successful outputs at least 24 hours old when another package finishes. The most recent successful output is retained. The receipt records the source commit and outcome; interrupted runs, unknown files, symlinks, changed outputs and outstanding leases remain for review. A `.retention-keep` anywhere in an output or its run directory protects it. Before distributing a development package, create `.retention-distributed` in its run directory; that protects the package and its associated symbols and provenance. Signed installer/release outputs and older unrecognized `release/` contents are outside this policy. `npm run development:retention` reports the current eligible set without deleting it; `-- --apply` applies the same checks. Deletion counts are not a measurement of space reclaimed.

When a completed task is retired, its sealed, unchanged, unleased and undistributed development package outputs are archived and expire after 24 hours under the same task-archive policy. Unknown and retained release files remain archived.

Packaged verification and the owned desktop smoke launcher automatically lease the latest managed package. A lease remains protective if its owner crashes, so investigate it rather than removing it by age. Other tools that use a managed package must acquire and release a lease through `leaseLatestDevelopment`; do not run files directly from a managed package without a lease. Before removal on macOS, the cleanup also requires a successful `lsof` inactivity check. An unavailable, denied or ambiguous process inventory preserves the output; other platforms currently preserve managed outputs until a reliable check exists. Hosted Windows packaging keeps its existing `release/win-unpacked` path. Renderer builds still use `dist`; this policy does not classify old renderer outputs or unknown packaging files as disposable.

[Asset preparation](../scripts/assets/assets.mjs) preflights source hashes, then reads one source at a time and rejects a source changed between those passes. Complete output validation and atomic publication remain required. Unchanged objects retain their bytes and encoder receipts.

[Build media](../scripts/assets/active-assets.mjs) copies files individually outside bundler asset buffers, validates copied hashes, rechecks selection identity and writes the media receipt after copying. [Package verification](../scripts/release/verify-package.mjs) compares renderer files lazily instead of retaining the entire renderer in a buffer map. Corruption and source-change checks remain intact.

Windows packaging excludes renderer npm modules already compiled into Vite output. Only Steamworks, Koffi and its target-platform native dependency remain as desktop node modules. Package verification rejects unexpected dependency files. Renderer dependencies remain production build inputs for license/SBOM coverage; they are not moved to development dependencies to hide them from packaging.

## Artwork preparation

[Startup](../src/ui/startup/prepare.ts) waits for current-screen essentials, fonts and the existing splash duration. Optional preparation chooses at most eight owned/offered ability images beyond current-screen artwork. It never resolves a future command or selects candidates from hidden draw order. Selection changes, backgrounding and disposal cancel obsolete preparation; no permanent image-element cache retains the library. Browser-managed decoded-image eviction remains outside application control.

Verify first-use battle, Collection, inspection and paging with uncached browser contexts. Missing images, degraded artwork, command delays or navigation regressions fail acceptance. The [UI review procedure](UI.md#required-review) defines rendered evidence.

The weekly/manual [performance workflow](../.github/workflows/performance.yml) includes native Windows startup, battle and menu observations. `npm run perf -- --electron --scenario resource-menus` repeats Collection, inspection, paging and Talents three times without changing gameplay checkpoints; this longer case is opt-in and does not widen ordinary captures. Captures record per-process working-set and peak-working-set values in KiB at readiness and action boundaries, plus Windows private bytes where available. GPU-process host RAM is not dedicated GPU memory. Browser heap, unpackaged Electron, Windows packaging, physical controls and Steam Deck remain separate verification scopes.

For a comparison, supply a full `memory_baseline` commit to the manual workflow. The native job captures three baseline/treatment pairs on one Windows runner with matching capture instrumentation and fixtures. Only capture tooling is overlaid in the baseline checkout; its production sources remain unchanged. Retain the overlay manifest and compare matching process types and action labels across trials; report medians and ranges without adding shared process working sets together. A single ordinary capture establishes observations, not a measured saving.

## Explicit maintenance

- `npm run assets:prune` plans removal of obsolete prepared objects after validating active outputs and checking source references; `-- --apply` removes only that exact eligible set under asset-preparation admission. Originals, active objects, referenced historical objects, symlinks and unexpected files survive. Retired tracked bytes remain recoverable from Git; this does not rewrite history
- Task creation links matching, healthy main dependencies. An explicit `npm run deps` also reconnects a missing task install when it matches; an existing private installation is never replaced automatically. `npm run deps -- --share` explicitly reconnects the caller's private install after closing that task's tools. Failed compatibility checks preserve private dependencies; installation never runs through a shared link
- Use [worktree cleanup](../scripts/README.md#worktree-operations) only after confirming a merged clean checkout is inactive. Clean/merged status alone is insufficient. Do not infer inactivity from age, remove ambiguous worktrees or alter another active task's dependencies
- On task retirement, ignored artifacts are copied and verified before the checkout is removed. Large duplicate files in later archives use independently writable copy-on-write clones when the filesystem supports them; byte hashes verify each clone, and ordinary copies remain the fallback. Each retirement checks at most 128 clones totaling 64 MiB to bound work under the integration lock. Older archives are never modified. Clone bytes are logical reuse, not measured physical savings
- Newly archived Playwright reports, test results, complete identifiable focused captures, sealed completed balance summaries, and complete identifiable performance and interaction runs expire after 24 hours, checked automatically when a task is created or finished. Traced performance, full balance replay, incomplete and unclassified reports remain preserved because they may contain source files or saves. A manifest and branch remain. Add `.retention-keep` inside an evidence directory, any of its parent directories, the archive root or its `files` directory to retain it; changed trees, symlinks and unclassified artifacts remain untouched. Existing archives and reports in active checkouts are not subject to this policy. Expiration occurs on the next task operation after the deadline, not on a background timer
- Historical evidence predating this policy, source/commit summaries, deliberate release artifacts and other unclassified files remain preserved. Review and separately approve deletion of historical evidence; quarantine and relocation alone do not reclaim space

Smaller image variants, lossy audio/image conversion, Git-history rewriting and package-manager migration are separate experiments. Consider them only after the byte-preserving changes are measured and reviewed.
