# Continuous integration

[Contributing](../CONTRIBUTING.md#verification) defines local completion and execution policy. This document describes the hosted verification pipeline and evidence contracts. The archived [CI speed improvement plan](archive/CI_SPEED_PLAN.md) retains measurements and rollout history.

CI selects the pinned npm version and installs with the lockfile. Install scripts require version-specific approval in `package.json`; `.npmrc` rejects unreviewed scripts. `npm run security:audit` checks all dependency advisories and retains the full report. The only temporary exception is the moderate `sprintf-js` formatter denial of service in the latest stable electron-builder download proxy logger (GHSA-hp3w-g68c-fv3c), expiring November 21, 2026; no player format strings reach that build-only path. New advisories and expired exceptions fail.

CI dependency installs omit non-gating audit/funding requests and have a three-minute deadline. CI runs static/content checks, units/DOM, a Linux browser build and Windows packaging independently after a small planning job. Browser tests use eight duration-balanced shards with one worker each; interaction replay consumes the same Linux build. The build manifest binds assets to the evaluated commit, run and attempt. Every consumer verifies the downloaded build hashes. `npm run verify:full` remains the complete sequential verification command; it is available locally within the same resource limits.

The final `verify` job allows workflow cancellation and runs even when upstream checks fail and requires every upstream job, every shard, the full discovered browser case set, passing unit results and the complete seeded interaction trace. Only the named development-preview browser case is intentionally excluded from production CI. Focused `.only` tests, unexpected skips, retries, missing cases, duplicate cases and interrupted suites fail the gate. The five-failure browser limit applies separately to each shard. Failed jobs may be rerun within the same workflow run and commit, reusing earlier successful jobs. Every recorded attempt must be positive and no later than the current attempt; unit evidence must match its successful job, and browser/interaction evidence must match the SHA-256 file inventory of the selected build. Missing evidence, another run/commit, or changed build bytes fail. A rebuilt artifact with different bytes requires rerunning its browser and interaction consumers. The final evidence manifest records the contributing attempts. See [GitHub rerun semantics](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/re-run-workflows-and-jobs).

CI retains unit JSON, per-shard blob reports containing screenshots/traces, merged browser JSON/HTML, player notes and Windows output for seven days. JSON attachments share the merged HTML report's `browser-html/data/` store; shard uploads keep the blob attachments rather than a second copy of `test-results/`. The `browser-review` artifact contains the merged report; `browser-shard-N` artifacts retain raw evidence. Missing reports are failures, not substitute passing summaries. Artifact collection and report merging run on failure where the runner remains available. Windows retains its own package verification and packaged startup/save/resume/isolation checks.

The build job creates an exact test-list plan from complete discovery, assigning the longest estimated cases first to the lightest shard. Estimates in `scripts/ci/browser-durations.json` affect scheduling only; new cases receive a default estimate and the final coverage gate still requires every discovered identity exactly once. Each successful gate exports refreshed estimates in `browser-review`; copy its `ci/browser-durations.json` to the checked-in estimate file when refreshing the baseline. Renames and new tests must never be omitted for missing timing history.

The workflow supports manual runs with one, four or eight browser shards for equivalent-coverage comparisons. Its `browser_runtime` input compares Chromium headless-shell installation with the official version-matched Playwright container, derived from the lockfile. Normal CI installs only the headless shell used by its existing browser configuration and interaction replay; headed local review still needs a full Chromium installation. Compare complete runs including container initialization before changing the default. Record completed-run timing with `node scripts/ci/ci-timings.mjs <run-id> [attempt]`; this reads GitHub metadata and writes timing JSON without executing tests. It requires an authenticated GitHub CLI. Timing captured inside the final job is provisional until that job finishes. Branch pushes with an open PR defer to PR verification; main pushes, tags and fork PRs retain their gates. A suppressed duplicate can have a successful workflow conclusion with verification skipped, so candidate qualification also requires the exact commit’s successful final `verify` job. Superseded automatic branch runs are cancelled; manual benchmarks run independently.

CI checks the JavaScript allowance after each production build and never builds twice solely to measure size. Full CI and release evidence must refer to the exact commit. See [release boundaries](RELEASE.md) and [required rendered review](UI.md#required-review).
